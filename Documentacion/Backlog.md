# Backlog sugerido para GitHub Projects

Este listado es una **propuesta** para registrar en GitHub Projects (no representa tickets ya creados).

| ID | Historia de usuario | Prioridad | Criterio de aceptación | Estado inicial |
|---|---|---|---|---|
| HU-01 | Como operador quiero registrar pacientes para incorporarlos al árbol. | Alta | Inserta datos válidos respetando BST. | Pendiente |
| HU-02 | Como operador quiero ver la jerarquía para entender el árbol. | Alta | Muestra raíz e hijos izquierdo/derecho. | Pendiente |
| HU-03 | Como operador quiero listar pacientes por puntaje para comparar riesgos. | Alta | InOrden retorna puntajes ascendentes. | Pendiente |

| HU-05 | Como operador quiero buscar un puntaje para consultar un registro. | Alta | Informa coincidencia o ausencia. | Pendiente |
| HU-06 | Como operador quiero exportar datos a TXT para disponer de un respaldo. | Alta | Archivo TXT UTF-8 creado. | Pendiente |

## Flujo de trabajo recomendado

Columnas: **Backlog → To Do → In Progress → Testing → Done**.

Al ejecutar las pruebas, cambia una tarea a **Done** únicamente si satisface su criterio de aceptación. Aunque el código venga incluido en el ZIP, debes validar los resultados en tu equipo y conservar evidencias reales. En GitHub puedes crear un Issue por cada HU y vincularlo al tablero.
